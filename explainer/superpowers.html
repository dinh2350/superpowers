2Cách dùng, tóm tắt

Bạn không gọi skill thủ công. Bạn chỉ trò chuyện, trả lời và duyệt. Phần còn lại agent tự chạy.

Cài một lần

Cài plugin vào agent bạn đang dùng. Mỗi công cụ (Cursor, Codex, Gemini CLI…) có cách cài riêng, xem README.

/plugin install superpowers@claude-plugins-official

Nói như bình thường

Mô tả việc bạn muốn. using-superpowers tự gọi skill phù hợp, bắt đầu bằng brainstorming.

Agent tự tra codebase, docs, DB trước, chỉ hỏi phần chỉ bạn quyết được.

Let's make a react todo list

Bạn quyết 4 điểm

Trả lời câu hỏi làm rõ, chọn hướng tiếp cận, duyệt design doc, duyệt plan, rồi nói “go”.

Agent tự chạy

Code theo TDD, review từng task, chạy kiểm chứng. Có thể tự làm vài giờ mà không lệch plan.

Cuối cùng bạn chọn: merge, mở PR hoặc giữ nhánh.

Phiên chạy lạ? (lặp việc, bỏ plan, skill không kích hoạt, tốn token) Hãy nói với agent: figure out what went wrong with superpowers in this session → chạy diagnosing-superpowers.

1

brainstorming

Trong luồngNâng cấp

Vấn đềAgent code ngay theo giả định, hoặc hỏi bạn những câu mà tool tự trả lời được (version thư viện, schema DB, lỗi trong log). Kết quả là đúng thứ bạn không cần.

Làm gìTự tra trước (code, docs đúng version trong lockfile, DB chỉ đọc, log, git), rồi báo lại: điều đã xác nhận kèm link, điều AI tự quyết, điều chỉ bạn quyết được. Hỏi từng câu về “muốn gì và vì sao”, tóm tắt lại cho bạn sửa, đưa 2–3 hướng để bạn chọn, rồi viết design doc HTML (có mục Evidence) và chờ bạn duyệt. Chưa duyệt thì chưa được code.

Dùng khiTrước mọi việc tạo mới hoặc đổi hành vi. Yêu cầu nhỏ và rõ (đổi màu icon) thì làm luôn. Không muốn hỏi đáp thì nói “cứ làm đi”.

4MCP catalog: nối agent với tool ngoài

Thư mục mcp/ là một menu 15 MCP server, đóng gói thành config sẵn để gộp vào project. Không bật gì mặc định: mỗi project chọn 3–5 server cần dùng. Đây không phải skill và không nằm trong luồng chính. Nó là phần thêm riêng của fork này, không thuộc Superpowers upstream.

Liên quan tới brainstorming: bước “tra trước khi hỏi” dùng docs thư viện, DB, log nếu session có tool tương ứng (context7, dbhub, sentry, datadog… trong catalog là những tool như vậy). Không có tool thì brainstorming không đoán, mà chuyển câu đó thành câu hỏi cho bạn.

Nguyên tắc

Vì sao catalog được đóng gói như vậy

Config, không phải code

Không chép code server vào repo. Mỗi mcp.json trỏ tới package npm đã pin version, hoặc endpoint do vendor host.

Menu, không phải bundle

Mỗi server bật lên là thêm tool definition vào context của mọi request. Chọn 3–5 server; catalog ghi số tool đã đo.

Quyền tối thiểu

Mặc định read-only hoặc có giới hạn. Lưu ý: read-only ở đây là ẩn tool, không phải rào quyền. Vẫn nên dùng credential ít quyền.

Không secret trong git

Config chỉ chứa tham chiếu ${VAR}. Tên các biến nằm trong mcp/.env.example.

Pin version

Server npm/PyPI được pin (Portainer pin tới minor vì phải khớp instance). Server vendor-hosted (GitHub, Supabase, Sentry, Datadog) không pin được, vendor kiểm soát hành vi.

Nói rõ đã test gì

README mỗi server kết thúc bằng mục “Last verified”: đã chạy gì, chưa chạy gì.

Cài vào project

Agent làm theo 6 bước, bạn xác nhận ở bước 2

Đọc catalog, xem stack

Agent đọc catalog.md và kiểm tra stack của project (package.json, pyproject.toml, supabase/, CI, .mcp.json có sẵn).

Đề xuất 3–5 server

Mỗi server một dòng lý do, và cái nào dùng CLI được thì nói. Agent chờ bạn xác nhận, không bật phần còn lại.

Đọc README từng server

Chú ý mục Auth và Risks của từng cái đã chọn.

Gộp config vào harness

Gộp mcp.json vào config của harness, không ghi đè cái đã có. Giữ mặc định ít quyền, không cấp quyền ghi vào production.

claude mcp add --scope project context7 -- npx -y @upstash/context7-mcp@4.7.3

Khai báo biến

Thêm tên biến vào .env.example của project, không bao giờ ghi giá trị thật. Kiểm tra .env đã được gitignore.

Kiểm tra và báo trạng thái

Chạy lệnh list/health của harness. Server đang “Pending approval” hoặc cần đăng nhập OAuth thì báo là đang chờ bạn, không báo là đã chạy.

Đã kiểm tra đến đâu (21/11/2026): 5 server stdio (context7, playwright, chrome-devtools, sequential-thinking, memory) khởi động được và liệt kê tool. Các server dữ liệu đã kiểm là bản hạn chế không có tool ghi (kubernetes chỉ thử với kubeconfig giả, chưa có cluster thật). Server remote (github, supabase, sentry, datadog) chỉ xác nhận endpoint tồn tại và đòi xác thực, chưa thử với credential thật.
Cẩn thận: dbhub và kubernetes cần file .toml chép vào thư mục .mcp/ của project. Thiếu file đó, dbhub ghi được vào DB.
Nguồn: README.md, skills/*/SKILL.md và mcp/. research-before-brainstorming không còn là skill riêng: nội dung đã gộp vào brainstorming (xem skills/brainstorming/references/research.md).
