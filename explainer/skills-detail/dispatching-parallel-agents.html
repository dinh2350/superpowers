2Khi nào dùng, khi nào không

Nguyên tắc cốt lõi: một agent cho mỗi vùng vấn đề độc lập, và để chúng làm việc đồng thời.

Dùng khi

Song song
  • 3+ file test fail với root cause khác nhau.
  • Nhiều subsystem hỏng độc lập.
  • Mỗi vấn đề hiểu được mà không cần ngữ cảnh từ vấn đề khác.
  • Không có state dùng chung giữa các cuộc điều tra.

Không dùng khi

  • Các lỗi liên quan nhau (sửa cái này có thể sửa luôn cái khác): điều tra chung trước.
  • Cần hiểu toàn bộ trạng thái hệ thống.
  • Các agent sẽ cản trở nhau (sửa cùng file, dùng chung tài nguyên).
  • Debug thăm dò: chưa biết cái gì đang hỏng.

3Mẫu bốn bước

Từ việc chia vùng tới việc ghép kết quả.

1

Xác định các vùng độc lập

Làm gìNhóm lỗi theo thứ đang hỏng. Ví dụ: file A test luồng duyệt tool; file B test hành vi hoàn tất batch; file C test chức năng hủy. Mỗi vùng độc lập: sửa phần duyệt tool không ảnh hưởng test hủy.

↑ Về diagram
2

Tạo task tập trung cho từng agent

  • Phạm vi cụ thể: một file test hoặc một subsystem.
  • Mục tiêu rõ: làm cho các test này pass.
  • Ràng buộc: đừng đổi code khác.
  • Output mong đợi: tóm tắt đã tìm thấy và đã sửa gì.

Prompt tốt làTập trung (một vùng vấn đề), tự đủ (mọi ngữ cảnh cần để hiểu vấn đề), và cụ thể về output (agent phải trả về gì). Ví dụ:

Fix the 3 failing tests in src/agents/agent-tool-abort.test.ts:

1. "should abort tool with partial output capture" - expects 'interrupted at' in message
2. "should handle mixed completed and aborted tools" - fast tool aborted instead of completed
3. "should properly track pendingToolCount" - expects 3 results but gets 0

These are timing/race condition issues. Your task:

1. Read the test file and understand what each test verifies
2. Identify root cause - timing issues or actual bugs?
3. Fix by:
   - Replacing arbitrary timeouts with event-based waiting
   - Fixing bugs in abort implementation if found
   - Adjusting test expectations if testing changed behavior

Do NOT just increase timeouts - find the real issue.

Return: Summary of what you found and what you fixed.

Dispatch song song

Làm gìPhát tất cả các lệnh dispatch subagent trong cùng một response: chúng chạy song song.

Subagent (general-purpose): "Fix agent-tool-abort.test.ts failures"

4

Review và tích hợp

  • Đọc tóm tắt của từng agent, hiểu đã đổi gì.
  • Kiểm tra xung đột: các agent có sửa cùng đoạn code không?
  • Chạy full test suite để xác nhận các fix chạy cùng nhau.
  • Spot check: agent có thể mắc lỗi hệ thống.

4Lỗi hay gặp và ví dụ thật

Bảng Common Mistakes và một ví dụ thật từ một phiên làm việc.

LỗiCách đúng
Quá rộng: “Fix all the tests” (agent bị lạc)Cụ thể: “Fix agent-tool-abort.test.ts” (phạm vi tập trung).
Không ngữ cảnh: “Fix the race condition” (agent không biết ở đâu)Có ngữ cảnh: dán thông báo lỗi và tên test.
Không ràng buộc: agent có thể refactor mọi thứCó ràng buộc: “Do NOT change production code” hoặc “Fix tests only”.
Output mơ hồ: “Fix it” (không biết đã đổi gì)Output cụ thể: “Return summary of root cause and changes”.

Ví dụ thật: 6 test fail trên 3 file sau một đợt refactor lớn

FileLỗiAgent đã làm gì
agent-tool-abort.test.ts3 lỗi (timing)Thay timeout bằng chờ theo sự kiện.
batch-completion-behavior.test.ts2 lỗi (tool không chạy)Sửa lỗi cấu trúc event (threadId đặt sai chỗ).
tool-approval-race-conditions.test.ts1 lỗi (execution count = 0)Thêm bước chờ tool async chạy xong.

Quyết định: các vùng độc lập (logic abort tách khỏi hoàn tất batch, tách khỏi race condition). Tích hợp: mọi fix độc lập, không xung đột, cả suite xanh.
