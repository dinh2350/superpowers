2Chạy 2 task song song

Skill không tự điều phối nhiều task. Mỗi lần gọi nó chỉ đảm bảo một workspace cô lập. Song song đến từ việc bạn mở nhiều session, mỗi session một worktree.

.git (dùng chung)history · branches · remote

Session Claude #1

Bắt đầu ở checkout chínhnhánh main
↓
.worktrees/task-askill tạo, branch task-a
↓
Code · test · commitchỉ chạm file trong task-a

Session Claude #2

Bắt đầu ở checkout chínhnhánh main
↓
.worktrees/task-bskill tạo, branch task-b
↓
Code · test · commitchỉ chạm file trong task-b
↓  hai session chạy cùng lúc, không đè file của nhau  ↓
Merge hoặc mở PR về main, từng nhánh một

Sai và đúng

Điểm dễ vấp nhất là Step 0

✗ Một session làm cả 2 task

  1. Gọi skill cho task A: tạo task-a, session đứng trong đó.
  2. Gọi skill lần nữa cho task B.
  3. Step 0 thấy GIT_DIR ≠ GIT_COMMON: “đã cô lập rồi”.
  4. Skill không tạo task-b, nhảy thẳng tới Step 2.

Kết quả: task B làm chung worktree với task A. Việc chặn này do Step 0 của skill, không phải do git (git vẫn cho tạo worktree lồng nhau).

✓ Mỗi task một session

  1. Mở session #1 ở checkout chính, gọi skill: tạo task-a.
  2. Mở session #2 ở checkout chính, gọi skill: tạo task-b.
  3. Mỗi session chạy Step 2, Step 3 trong worktree của nó.

Nếu harness đã tạo sẵn worktree cho session (ví dụ --worktree), Step 0 nhận ra và dùng luôn. Cũng đúng, vì mỗi session vẫn có chỗ riêng.

Tách riêng và dùng chung

Phần này là hành vi của git, không phải của skill

Tách riêng cho mỗi worktree

An toàn song song
  • File đang sửa và staged changes
  • Branch (mỗi worktree một branch)
  • node_modules, build output

Hệ quảStep 2 và Step 3 phải chạy lại ở từng worktree: cài dependency và chạy test baseline riêng.

Dùng chung, dễ xung đột

Cẩn thận
  • .git: history, remote, danh sách branch
  • Port dev server (hai task cùng chạy cổng 3000 sẽ đụng nhau)
  • Database local, file .env nằm ngoài git

Giới hạn của gitMột branch không thể checkout ở hai worktree cùng lúc, nên mỗi task cần tên branch khác nhau.

Muốn một session tự chạy nhiều task cùng lúc? Đó là việc của skill khác trong repo này, như dispatching-parallel-agents và subagent-driven-development, không phải của skill này.

Kiểm tra

0

Phát hiện cô lập

Luôn chạy

Vấn đềAgent tạo worktree lồng trong worktree, hoặc tạo khi bạn không muốn. Nhìn bằng mắt rất dễ nhầm, vì isolation do harness tạo và submodule đều đánh lừa việc “đoán”.

Làm gìChạy lệnh so sánh thư mục git của workspace với thư mục git chung:

GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" 2>/dev/null && pwd -P)
BRANCH=$(git branch --show-current)

# Chống nhầm submodule (cũng làm GIT_DIR ≠ GIT_COMMON):
git rev-parse --show-superproject-working-tree 2>/dev/null
Kết quảSkill làm gì
GIT_DIR ≠ GIT_COMMON, đang ở một nhánhBáo “Already in isolated workspace at <path> on branch <name>”, nhảy tới Step 2
Như trên nhưng detached HEADBáo “(detached HEAD, externally managed). Branch creation needed at finish time”, nhảy tới Step 2
Lệnh submodule trả về một đường dẫnĐang ở submodule, không phải worktree: coi như repo thường
GIT_DIR = GIT_COMMON (repo thường)Có preference của bạn rồi thì theo. Chưa có thì hỏi: “Would you like me to set up an isolated worktree? It protects your current branch from changes.”
Bạn từ chốiLàm tại chỗ, nhảy tới Step 2

Dùng khiLuôn là việc đầu tiên. “Chắc mình không ở trong worktree” không phải lý do để bỏ qua.

Tạo workspace

1a

Tool native

Ưu tiên

Vấn đềGõ thẳng git worktree add dù harness đã có tool riêng sẽ tạo “trạng thái ma”: harness không thấy, không quản lý, không dọn được.

Làm gìTìm xem mình có sẵn cách tạo worktree không: tool như EnterWorktree, WorktreeCreate, lệnh /worktree hoặc cờ --worktree. Có thì dùng và nhảy tới Step 2. Tool native lo luôn chỗ đặt thư mục, tạo branch và dọn dẹp.

Dùng khiLuôn thử trước. Bỏ qua bước này là “lỗi số 1” theo chính skill.

1b

git worktree add

Fallback

Vấn đềKhông có tool native thì phải tự tạo, và dễ chọn bừa thư mục hoặc quên ignore.

Làm gìChọn thư mục theo thứ tự ưu tiên bên dưới, kiểm tra đã ignore, rồi tạo:

git check-ignore -q .worktrees 2>/dev/null \
  || git check-ignore -q worktrees 2>/dev/null
# chưa ignore → thêm vào .gitignore + commit, rồi:
git worktree add "$path" -b "$BRANCH_NAME"
cd "$path"
Ưu tiênChọn thư mục
1Chỉ dẫn bạn đã khai báo (dùng luôn, không hỏi)
2.worktrees/ hoặc worktrees/ đã có sẵn. Có cả hai thì .worktrees/ thắng
3Không có gì thì mặc định .worktrees/ ở root

Dùng khiChỉ khi 1a không áp dụng. Nếu sandbox chặn (lỗi permission), skill báo bạn rồi làm tại chỗ và chạy setup ở đó.

Vấn đềBắt đầu trên nền đã đỏ thì mọi lỗi về sau đều mơ hồ: không biết do mình hay do có sẵn.

Agent hay tự bào chữa thế nào

Common Rationalizations của skill: dấu hiệu bạn nên nhắc agent
Agent tự nhủThực tế
“Rõ ràng mình không ở trong worktree, khỏi kiểm tra”Chạy Step 0. Isolation do harness tạo và submodule đều làm mắt thường nhầm. Lệnh phát hiện mới là câu trả lời.
“git worktree add nhanh hơn đi tìm tool native”Tool native lo chỗ đặt, branch và dọn dẹp. Bỏ qua nó là lỗi số 1: sinh “trạng thái ma” mà harness không thấy.
“Thư mục worktree chắc đã được ignore rồi”Chạy git check-ignore. Không ignore thì cả cây worktree bị commit vào repo.
“Tên thư mục nào cũng được”Chỉ dẫn rõ ràng của bạn thắng thư mục project-local có sẵn, thứ này lại thắng mặc định .worktrees/.
“Workspace mới tinh, test baseline để sau”Baseline bẩn làm mọi lỗi sau đó mơ hồ. Chạy test ngay. Có đi tiếp khi test đỏ hay không là quyết định của bạn.
